SUBJECT: Sync profiles.email when auth.users.email changes
STATUS: New
TYPE: Feature
---
Follow-up from #93 (adversarial review).

`public.profiles.email` is a mirror of `auth.users.email`, populated once by the `handle_new_user()` trigger at signup. There is no mechanism to keep it synchronized if a user's Auth email is later changed via the GoTrue email-change flow -- the mirror would silently go stale.

#93 reconciled `profiles.email` from `auth.users.email` once (at migration time), added a UNIQUE constraint, and locked it against self-service mutation via RLS. That makes the mirror trustworthy at deploy time, but it does not keep it in sync afterward, and the column is now protected from self-repair.

This is a pre-existing architectural gap (true on main before #93), surfaced by the Codex adversarial review of #93. It is low-risk today because the app exposes no email-change UI, but should be closed if/when an email-change feature is added.

Proposed fix: add a SECURITY DEFINER trigger on `auth.users` for `UPDATE OF email` that atomically updates `public.profiles.email`, and test the email-change path. Alternatively, stop trusting the mirrored column and read identity from `auth.users` via a service-role path.
